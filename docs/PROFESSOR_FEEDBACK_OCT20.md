녹음에 **「분류 표를 만들어라」는 없다.** 교수 요청은 유형이 나뉘고 근거가 있으며 복수를 고르게 하라는 것이다. 표·KB `group` 필드는 팀 구현 방법이다.

---

## 한 줄

증상 입력 방향은 유지한다. 남은 약 10일은 **유형화된 증상 → 닫힌 코드 → 규칙으로 보험 종류 연결 → 한눈에 보이는 결과**가 우선이다. 프라이버시 서사와 충돌하지 않으나, 둘을 동시에 깊게 가면 제출(작동 영상)이 위험하다.

---

## 교수님이 이번엔 무엇을 말했는가

증상 입력은 좋다고 하셨다. 이번 중심은 프라이버시가 아니라 **증상 유형화, 뒷단 근거 데이터, 입력 처리 설계, 결과가 보이는 UI, 뒷단 흐름도 1페이지**다.

| # | 요청 | 해석 |
|---|------|------|
| 1 | 증상을 두 유형으로 나누고 복수 선택 | **평소 잘 느끼는 군**(두통·소화불량 등)과 **잘 안 느껴지지만 초기 신호일 수 있는 군**(예: 다리가 근지러움 — 혈압·혈당과 연관될 수 있다는 **예시**, 확정 진단 아님). 유형화에 **근거**. 둘을 복합·복수 선택. 「분류 표」라는 숙제는 아님 |
| 2 | 증상–질환 연결은 뒷단 의학적 기준 | LLM에 “이 증상이 뭐야?”를 묻지 말 것. 면담의 “공단 빅데이터 API”는 **공공데이터포털 Open API(심평원 질병정보, 공단 상병 통계)**로 정정. 약관 검색보다 **어떤 보험이 있는지를 연결**. 월 납입별 추천은 시간 남으면 |
| 3 | 입력 처리 순서와 근거 | 클릭한 값과 적어 넣은 값이 모델에 가기 전 처리 설계. API 먼저 vs AI 먼저는 **팀이 고른다**. 아래 순서는 팀 선택이지 교수 확정이 아님 |
| 4 | 우선순위·제출 | 핵심 먼저. **보이는 UI**가 심도 있는 동작보다 앞설 수 있음. 작동하지 않으면 점수 없음. **구현 영상** 필수. API가 어려우면 작동 설계 먼저, API는 나중에. PPT에 **뒷단 1페이지** 필수 |
| 5 | 포트폴리오 | 구현 못 한 고민도 자소서·면접 소재. 감점이 아니라 강점 |

전사 주의: “체크를 복합적으로”가 “탱크를”로 잘못 받아적힌 것으로 보여 **복수 선택**으로 본다. 질환 연관은 **가능성**만, 진단 UI 금지.

충돌하지 않는다. 다만 **10일에 비해 범위가 크다.**

| | 지난번 (PRIVACY 재정의) | 이번 |
|--|-------------------------|------|
| 주서사 | 최소수집·비식별·원본 미저장 | 증상 유형 + 근거 데이터 + 결과 UI |
| 결정권 | 규칙, LLM은 문장화 | 동일. LLM에게 증상 해석을 맡기지 말 것 |

이번에 꼭 할 것 / 흐름도에만 넣을 것 / 후속으로 말할 것을 나눈다. “고민했지만 구현은 못 했다”는 후속 슬라이드로 남긴다.

## 지금 코드와의 갭

### 이미 있는 것

- 칩 **복수 선택**, 직업군·걱정, `POST /v1/assess` · `/v1/guidance` ([`frontend/index.html`](../frontend/index.html), [`sangtae.js`](../frontend/sangtae.js))
- 규칙 엔진이 후보를 정함. 증상 코드가 있으면 자유문을 버림 ([`GuidanceService`](../src/harag/guidance/service.py))
- 형식 PII 마스킹, 출력 가드(진단 단정 완화)
- 보장 **유형** 4종: 실손 통원·입원·검사·상해 ([`kb.yaml`](../src/harag/guidance/kb.yaml))
- 증상 5종: 두통, 하지 경련(다리 쥐), 요통, 소화불량, 피부. 질병관리청 국가건강정보포털 출처가 일부 붙어 있음
- 시퀀스 3장: [SEQUENCE_DIAGRAMS.md](SEQUENCE_DIAGRAMS.md)

LLM에게 증상을 해석시키지 말라는 요청은 **이미 규칙 엔진과 같다.**

팀 선택 입력 순서(목표, 10일) — 교수가 두 순서를 제시했고, 안정적인 쪽을 고르라고 했다:

```text
두 유형 칩 + 자유 입력 (근거 있는 유형화, 복수 선택)
 → 형식 PII 마스킹
 → 닫힌 증상 코드
 → 가능 질환 + KCD + 보장 종류 (팀 규칙. 「어떤 보험이 있는지 연결」의 구현)
 → 연령·성별 통계 (심평원·공단 Open API, 실패 시 JSON 캐시)
 → LLM은 위 사실만 문장화
```

`AI → API`는 모델이 증상 의미를 만들 수 있어 팀이 쓰지 않기로 했다. API에는 **사용자 문장이 아니라 상병코드(KCD)만** 나간다. 발표에서는 “입력이 명확해야 결과가 명확하다”로 **이 팀 선택을** 말한다. **특정 논문 DOI는 이 메모에 넣지 않는다.**

### 없는 것 / 어긋난 것

- 칩이 두 유형으로 나뉘어 보이지 않는다. (팀 UX로 그룹 헤더를 둘 수 있음. 교수 숙제가 「표」는 아님.)
- 교수 예시 「다리가 근지러움」은 지금 `leg_cramp`(근육 경련) 및 `skin`(가려움→피부과)과 **같지 않다.** 초기 신호 군에 넣으려면 의학 출처를 붙인 뒤에만.
- 결과 화면이 “보험 종류 한눈에”가 아니라 상태 카드 + 보장 유형 목록이다.
- 심평원·공단 **Open API 연동은 없다.** 매핑 진실원천은 큐레이션 KB다. 공공 API는 통계 근거를 붙이는 역할이며, 시연은 JSON 캐시 폴백이 필수다.
- persist 0·canary 집계는 설계 목표이지 라이브 지표가 아니다.

## 공공데이터 역할 — NHIS 플랫폼이 아니라 Open API

면담의 “건강보험공단 빅데이터 API”는 두 기관이 섞여 있다.

| | 건강보험공단(NHIS) 빅데이터 플랫폼 | 공공데이터포털 Open API · 파일 |
|--|-----------------------------------|--------------------------------|
| 형태 | 연구용 가명 표본 (2026 하반기 시범, 100만 명 등) | 심평원(HIRA) 질병정보서비스 REST(XML), 상병마스터 파일, 공단 상병 진료인원 파일 |
| 이용 | nhiss 신청·확약·내부 심의 | 포털 회원가입·활용신청·서비스키 |
| 10일 | **불가** (심의·자격 미확인) | **가능.** 실패해도 JSON 캐시로 시연 |

발표에서 쓸 이름: **공공데이터포털 오픈 API(심평원 질병정보서비스, 공단 상병 통계)**.

### 쓸 만한 후보 (통계 근거만)

| 데이터 | 용도 |
|--------|------|
| 심평원 질병정보서비스 | 질병명·KCD 조회, 성별·연령·입원/외래 빈도 |
| 심평원 상병마스터 | 코드 정규화, 성별·연령 제약 |
| 공단 특정 상병 진료인원·내원일수 | 질환별 규모. 5 미만은 비식별 |
| 심평원 암 상병 진료비 | “보장이 왜 필요한가” 비용 참고. **비급여 제외** |
| 공단 검진 표본 | 사용자가 수치를 안 넣으므로 후순위 |

엔드포인트 URL은 포털 명세가 바뀔 수 있고, 일부 페이지는 404였다. **코딩 전에 명세 페이지에서 경로를 확인한다. 이 문서에 가짜 URL을 적지 않는다.**

### 이 데이터로 못 하는 것

1. **증상 → 질환** 없음. 유형화 근거는 공공 건강정보 등으로 **직접 큐레이션**.
2. **질환 → 보장 유형** 없음. 팀이 규칙으로 구현하는 「어떤 보험이 있는지 연결」.
3. 통계 ≠ 확진. 일차 진단명 기준일 수 있다. UI는 **가능성 참고 통계**.
4. 진료비는 비급여를 빼 실손 비용을 과소 추정할 수 있다. 한계를 명시.
5. 라이선스는 데이터마다 다름. 졸업 발표는 무방하나 상용·포트폴리오 재배포 전 확인.

공공 API는 증상을 해석하지 않는다. **직접 만든 매핑에 통계를 붙인다.**

## 발표에서 쓸 문장

- 작동: 평소 증상과 잘 안 느껴지는 초기 신호를 나눠 복수로 고르게 하고, 코드로 정규화한 뒤 규칙이 실손 보장 종류를 고르며, 심평원·공단 통계(캐시)를 붙이고 LLM은 그 사실만 설명한다. 분류 표를 숙제로 받은 것이 아니다.
- 쓰지 않는 것: NHIS 빅데이터 플랫폼 실시간 표본, 사용자 문장을 공공 API에 보내는 것.
- 하지 않는 것: 진단, 상품명 권유, 가입 심사, 월 납입 산출.
- 고민했으나 이번엔 안 넣은 것: NHIS 시범사업 신청, canary, 금액별 추천. 자소서에 적는다.
