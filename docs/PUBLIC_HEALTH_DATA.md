# 두 유형 증상 분석용 공공의료데이터

증상 칩을 **자주 느끼는 불편**과 **놓치기 쉬운 불편**으로 나누는 근거는 LLM이 아니라 KB 큐레이션(질병관리청 국가건강정보포털 개요)이다. 공공데이터는 그 분류를 **통계·규모로 검증·설명**할 때 붙인다. 확진·추천이 아니다.

면담 정리와 같은 맥락: [PROFESSOR_FEEDBACK_OCT20.md](PROFESSOR_FEEDBACK_OCT20.md).

## RESULT 근거 사슬

| 블록 | 내용 | 데이터 | LLM |
|------|------|--------|-----|
| **참고 해석** | 증상 묶음 종합 (확진·전조·유병률 금지) | KCD·areas·클러스터 | 3문단 요약만 |
| **같이 보면 참고할 수 있는 영역** | 닫힌 `symptom_clusters` + 관련 가능 상병군 | `kb.yaml` 큐레이션 | 병명 발명 금지 |
| **코호트 카드** | 연령·성별 청구 규모 | HIRA `ref_stats` / `cluster_stats` | 숫자 변조 금지 |
| **증상에 알맞은 보험 2개** | 점수 선정 + why | ready 라이브러리 | 선정 목록만 |

추적 경로: **선택 증상 ↔ (증상 묶음) ↔ 관련 가능 영역 ↔ 연령·성별 청구 코호트 ↔ 보장·설명서**.

### 직업 통계 (M3) — 어떻게 채울지

현재 UI는 “직업별 질환 통계는 아직 없습니다. 보험 규칙 가중·맥락만 반영”이라고 명시한다.

채우려면 아래 중 하나를 **파일로 큐레이션**해 `occupation_stats` 슬롯에 적재한다.

- 고용노동부·안전보건공단 산업재해·직업병 통계 (업종별)
- (제한적) 공단 특정상병 파일의 연령 보강
- NHIS 표본은 단기 시연에 비권장

## 쓰지 않는 것

- 사용자 자유문을 공공 API에 보내는 것
- 공공 통계를 진단·유병률·전조·위험 점수로 표시하는 것
- 통계 없는 직업 유병률을 LLM이 만들어 내는 것
- A/클러스터 숫자를 LLM이 새로 만들거나 바꾸는 것

## 제품에서의 읽기

1. 칩 유형화 = 포털 개요 기반 큐레이션  
2. 「이 증상에 대한 참고 해석」 = 묶어 본 참고 해석  
3. 「같이 보면 참고할 수 있는 영역」 = 증상 묶음 + 연령·성별 코호트  
4. 심평원·KCD 카드 = 증상별 숫자 증명  
5. 「증상에 알맞은 보험」 = 2상품
