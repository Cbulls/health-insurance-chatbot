# 두 유형 증상 분석용 공공의료데이터

증상 칩을 **자주 느끼는 불편**과 **놓치기 쉬운 불편**으로 나누는 근거는 LLM이 아니라 KB 큐레이션(질병관리청 국가건강정보포털 개요)이다. 공공데이터는 그 분류를 **통계·규모로 검증·설명**할 때 붙인다. 확진·추천이 아니다.

면담 정리와 같은 맥락: [PROFESSOR_FEEDBACK_OCT20.md](PROFESSOR_FEEDBACK_OCT20.md).

## 권장 소스

| 데이터 | 역할 | 상태 |
|--------|------|------|
| [심평원 질병정보서비스](https://www.data.go.kr/data/15119055/openapi.do) | KCD별 성별·연령·입원/외래 청구 빈도 | **연동됨** (`src/harag/guidance/hira.py` + `hira_cache/`). 평소군은 외래 청구가 많은 경우가 많고, 놓치기 쉬운 군은 상대적으로 드물거나 입원 비중을 참고할 수 있음 |
| 질병관리청 국가건강정보포털 | 증상 개요·유형 문구의 출처 | API 아님. 칩 ⓘ·`kb.yaml` `source`에 사용 |
| [공단 특정 상병 진료인원](https://www.data.go.kr/data/15157534/fileData.do) | 연도·연령별 실인원 규모 | 파일/변환 API. 특정 코드 묶음 위주라 전 증상 확장에는 한계. **후속** |
| [공단 상병 진료인원·내원일수](https://www.data.go.kr/data/15160003/fileData.do) | 내원일수·진료인원 | 위와 유사. **후속** |
| 심평원 상병마스터 (hira.or.kr 자료실) | KCD 정규화 | 매핑 정확도 보강용 |
| NHIS 빅데이터 플랫폼 | 가명 표본 | 신청·심의 필요. 학부 단기 시연 **비권장** |

## 쓰지 않는 것

- 사용자 자유문을 공공 API에 그대로 보내는 것
- 공공 통계를 진단·유병률로 표시하는 것
- NHIS 플랫폼 실시간 표본만으로 시연하는 것

## 제품에서의 읽기

1. 칩 유형화 = 포털 개요 기반 큐레이션  
2. 규칙 엔진 = 보장 종류 연결  
3. 심평원 통계 = 결과 「참고 통계」에 청구 빈도만 표시 (캐시 폴백 가능)
